Mod profiles for Vintage Story's mod manager. Keep several named sets of enabled mods and switch between them with one click, pick which installed version of a mod each profile uses, and update your mods from the mod DB - all inside the game's own Mods screen.

Main-menu Mods screen: profile tabs above the mod list, mod cards with update buttons, the update status with Update all, and Apply Profile

How to open it

  • Main menu: click Mods. The profile tabs sit above the mod list and Apply Profile is under it.
  • In game: the Mod Profiles dialog has no key by default. Bind one under Settings > Controls (entry "Mod Profiles"); that key then opens and closes it.
  • Heads-up: the game runs no mod code until a world loads, so on a normal launch the main-menu tabs appear after you have loaded a world once. The in-game dialog works from the first world. To have the tabs from the moment the game opens, use Add Shortcut - see Load at startup below.

Features

  • Profiles as tabs - one tab per profile above the mod list. + copies the profile you are looking at; right-click a tab to rename or delete it.
  • Apply Profile - makes the profile you are viewing the one the game loads. It writes the game's own settings, so the game boots with that set every time.
  • One card per mod, any number of versions - several installed versions share one card with a version drop-down; each profile can use a different version.
  • Clean mod cards - fixed-height cards with a hover tooltip for authors, description, dependencies and update details.
  • Update checking - a background check against mods.vintagestory.at, a yellow marker on cards with an update, Update all, and a (Retracted) note on releases pulled from the DB.
  • Fix dependencies - switches on (or downloads) what a mod needs, for the profile you are viewing.
  • Singleplayer worlds remember their mods - starting a singleplayer world with the wrong profile asks you first and offers the matching one. Nothing is recorded for multiplayer servers.
  • In-game dialog - manage profiles without leaving the world (bind its key in Settings > Controls).
  • Restart only when it is real - a notice appears only when you switch a mod you already played this session to a different version. Enabling and disabling mods never needs a restart.
Profiles in detail
Right-clicking a tab opens the rename panel under it: name field, Delete, Enter saves, Esc cancels
  • Viewed vs active. The selected tab is the viewed profile - the one your clicks edit. The active profile is the one the game will load. The Mods screen always opens on the active profile.
  • Toggling a mod edits the viewed profile only. On the main menu, if you are viewing the active profile, the change also goes straight to the game, like vanilla's switch. Edits to any other profile wait for Apply Profile.
  • + creates "Profile N" as a copy of the profile you are viewing.
  • Rename / delete: right-click a tab. Enter saves, Esc cancels. Delete needs a second click. The last profile cannot be deleted; deleting the active one applies the next.
  • Your first profile is created from whatever was enabled when BetterMods first ran, so nothing changes until you change it.
  • Mods the game enables or disables by itself (for example when joining a server) are folded into the active profile, so the next Apply does not silently undo them.
  • Blocklisted mods stay blocked - a profile cannot re-enable them.
  • Profiles live in VintagestoryData/ModConfig/bettermods.json (plus a .bak). If that file exists but cannot be read, BetterMods says "Not saving - config unreadable" and never overwrites it.
The in-game dialog

Opening it: it has no key by default. In Settings > Controls, find Mod Profiles and assign any free key; that key opens and closes the dialog from then on.

The same tabs, cards, version picker and Apply Profile, inside a running world. In game, Apply Profile takes effect the next time you load a world - mods cannot be unloaded from the world you are in, but no restart is needed.

Card tooltip: name, mod id, version and side on one line; authors; description; then dependencies, an update for an older game version and the retraction reason
Two installed versions of one mod: the version drop-down open under the version label, the one in use ticked
  • Fixed-height cards: icon, title and version on the top line, buttons along the bottom. A status line appears only for a load error.
  • Hover tooltip: name, mod id, version, type and side on one line; authors, contributors and description; then a footer with dependencies and any update, retraction or dependency detail.

  • (Retracted) after the version: the installed release was retracted on the mod DB. The tooltip shows the reason.
  • Version drop-down: with several versions of one mod installed, click the arrow on the version label and pick one. It is switched on in the viewed profile and the others are switched off.

  • Core-mod protection: switching off game, survival, creative or another core mod in a profile asks first, on both screens.
Update checking and installing
Yellow update markers with Update to buttons: updates for an older game version show (1.22), an exact-version update does not, and a retracted release shows (Retracted)
Tooltip of a mod with an update tagged for the exact game version: the green Update available line
  • When: once per session in the background, the first time you open the Mods screen or the in-game dialog; again on Reload Mods or the status button. Never on a timer.
  • Exact game version: an update is offered only when the DB has a newer release tagged for the exact game version you run (e.g. 1.23.0-pre.1). Never a downgrade, never stable-to-pre-release.
  • Older game version: if there is nothing for your version, BetterMods also looks at the newest stable version before it (e.g. 1.22.7). Those show as a yellow Update to x.y.z (1.22), ask for confirmation, and are not part of Update all.
  • Honest wording: on a preview build few mods are tagged yet, so the status says "No newer releases for 1.23.0-pre.1" rather than "up to date".
  • Old versions are kept - the new file goes next to the old one and both stay in the version drop-down.
  • Only the profile you are viewing switches to the new version; every other profile keeps what it had.
  • Main menu only - the in-game dialog tells you about updates; installing happens on the Mods screen.
  • Core mods, BetterMods itself and mods inside the game folder are not checked.
Fix dependencies
  • Appears on a mod that is on in the viewed profile and has a dependency that is missing, switched off, or too old. The tooltip lists each problem.
  • Prefers what you have: switches on the newest installed version that satisfies the requirement.
  • Downloads what is missing (main menu only): the newest release for your game version, or, after asking, one for the older game version.
  • Follows the chain: a new dependency's own dependencies are handled too.
  • Viewed profile only. Other profiles are not changed.
  • It will not "fix" requirements on game, survival, creative or other core mods - those are reported in the tooltip and left to you. Anything it could not do is listed, never half-done silently.
Worlds remember their profile and mods (singleplayer only)
Singleplayer world list: hovering a world shows, at the bottom of its tooltip, the BetterMods profile it is bound to and the mods it last loaded with
  • Singleplayer only. World binding, mod-list recording and the world-start prompt apply to your own singleplayer worlds. On a multiplayer server BetterMods binds nothing, records nothing and posts no chat notices.
  • Every singleplayer world start binds the world to the active profile, and BetterMods records which mods the world actually loaded with.
  • One prompt, only when it matters: mods the world used are not enabled; another profile matches the world exactly; or the world is bound to a different profile. Version differences and extra mods alone never ask.
  • Switch to ... applies the matching profile and starts the world. Play with ... starts it as it is and rebinds it, so you are not asked again. Cancel returns to the world list.
  • World list tooltip: hover a world to see its profile and the mods it last loaded with.
  • Copied worlds: a small record is also kept inside the save file, so it travels with the world to another PC. Never written into a read-only save, one being upgraded, or one being repaired.
Open mod page and trusted links
  • Open mod page is on the card of every mod the update check found on the DB.
  • The first time, you choose Cancel, Always trust mods.vintagestory.at, or Open. After "Always trust", mod pages open without asking.
  • Trust applies only to the mod page links BetterMods builds itself. Every other link keeps the game's normal confirmation.
  • To undo: with the game closed, remove the site from "TrustedLinkHosts" in ModConfig/bettermods.json.

Saved playstyles (Accepted feature creep)

Accepted feature creep. Nothing to do with mod profiles - it lives in BetterMods because a separate mod just for two buttons on one screen was not worth it.

Create New World with Save and Delete playstyle, and a saved custom playstyle
  • On Create New World, two buttons sit at the right of the Select A Playstyle row (just Save and Delete on a narrow window). Save playstyle saves the selected playstyle, everything you changed under Customize and the world height under a name of your choice. The seed and world name are never saved.
  • Saved playstyles appear in the playstyle list, tagged Custom with the line "Based on <base>, world height <n>.", and in Customize's dropdown. Picking one applies all of its settings and its height.
  • Delete playstyle removes the selected saved playstyle after asking - never the game's own playstyles, ones mods define in worldconfig.json, or files a mod marked read-only.
  • Worlds stay vanilla: a world is created as the saved playstyle's base (e.g. Survive and Build) with its settings applied in full, and loads the same without BetterMods.
  • If the base playstyle's mod is not installed, the entry is greyed out and tagged Unavailable, with the reason. Settings for missing mods are skipped and the row says so.
For mod authors: the .vsplaystyle format

Any mod can add playstyles to that list by writing <name>.vsplaystyle files (UTF-8 JSON, name from A-Z a-z 0-9 _ -) directly into <data path>\Playstyles\ - exactly what api.GetOrCreateDataPath("Playstyles") returns (follows --dataPath).

{
  "format": "vsplaystyle",
  "formatVersion": 1,
  "name": "Hardcore Survival",
  "description": "Survive and Build with one life and harsh winters.",
  "basePlaystyle": "surviveandbuild",
  "worldHeight": 320,
  "worldConfig": { "playerlives": "1", "harshWinters": "true", "graceTimer": "0" },
  "readOnly": true,
  "author": "YourMod",
  "createdBy": "yourmod 1.0",
  "gameVersion": "1.23.0-pre.1"
}
  • basePlaystyle (required) is a real playstyle code; the world is created as it. worldConfig holds sparse overrides keyed by world-config attribute code, as in a worldconfig.json playstyle. Effective settings: attribute defaults, then the base playstyle, then these.
  • worldHeight (default 256) is rounded to Customize's slider: 128-512 in steps of 64 (to 2048 for creativebuilding).
  • readOnly: true for files your mod supplies: BetterMods never deletes or overwrites them. A read-only file is tagged "By <author>" from its author, or "From a mod" when that is empty.
  • Optional settingMods (attribute code to mod id) only explains skipped keys ("mod X not installed").
  • Data only: read as plain JSON, nothing executed. At most 200 files of 64 KB. Bad JSON, wrong format, a newer formatVersion or a missing base: skipped and logged. Each value is checked against its attribute: ranges clamped, dropdown values must be allowed values, text may not contain < or >; a rejected value keeps the base value.

Installation

  1. Download the zip from the Files tab (1.23: the latest; 1.22: BetterMods 1.2.0).
  2. Drop it into your mods folder without unzipping (Windows: %APPDATA%\VintagestoryData\Mods\ - the Open Mods Folder button gets you there).
  3. Start the game. Load a world once (or set up Load at startup, below) and open Mods on the main menu. For the in-game dialog, bind a key to Mod Profiles under Settings > Controls.

Load at startup (optional)

Vintage Story runs no mod code until a world loads, so BetterMods normally reaches the main menu only after your first world. A small .NET startup hook fixes that: the .NET runtime runs it before the game starts, it waits for the game to come up and loads BetterMods' patches, so the profile tabs are there from the first screen.

  1. Load any world once (the button is also in the in-game dialog).
  2. On BetterMods' own card, click Add Shortcut.
  3. Start the game from the new desktop shortcut Vintage Story (BetterMods).
BetterMods' own card with the Add Shortcut button, greyed out once the shortcut exists
  • Nothing to copy by hand. BetterMods writes the hook to VintagestoryData\ModConfig\BetterMods\BetterModsHook.dll and keeps it in step with the installed BetterMods, even after updates.
  • For that launch only. The shortcut sets DOTNET_STARTUP_HOOKS just for the game it starts, and only if the hook file exists - delete the file and the shortcut still starts a normal game.
  • The button greys out once the shortcut exists. Other ways of starting the game keep working as before.
  • Off means off: switch BetterMods off in the mod manager and the hook does nothing either, from the next launch.
  • Zip installs: the first launch after installing or updating BetterMods shows the vanilla screen until a world loads (the game only unpacks zips then).

Do not set DOTNET_STARTUP_HOOKS globally (no setx, no system environment variable) and do not edit Vintagestory.runtimeconfig.json. If the variable points at a missing or invalid file, the game does not start at all, with no error; every .NET program would pick up a global setting; and game updates overwrite the runtimeconfig file. Use the shortcut, or one of the per-launch methods below.

Making the Windows shortcut by hand

Right-click the desktop, New > Shortcut, then in its Properties set:

Target%SystemRoot%\System32\cmd.exe /c if exist "%APPDATA%\VintagestoryData\ModConfig\BetterMods\BetterModsHook.dll" (set "DOTNET_STARTUP_HOOKS=%APPDATA%\VintagestoryData\ModConfig\BetterMods\BetterModsHook.dll") & start "" "GAMEFOLDER\Vintagestory.exe"
Start inGAMEFOLDER
RunMinimized
IconGAMEFOLDER\Vintagestory.exe

Replace GAMEFOLDER with your install folder (installer default: %APPDATA%\Vintagestory). With a custom data folder, use <data folder>\ModConfig\BetterMods\BetterModsHook.dll for both hook paths and add --dataPath "<data folder>" at the end.

If the Target box cuts the line off (it holds about 260 characters), save this as Vintage Story (BetterMods).cmd and launch from it instead:

@echo off
set "HOOK=%APPDATA%\VintagestoryData\ModConfig\BetterMods\BetterModsHook.dll"
if exist "%HOOK%" set "DOTNET_STARTUP_HOOKS=%HOOK%"
start "" "GAMEFOLDER\Vintagestory.exe"
Linux and macOS

No shortcut is made there. Hover BetterMods' card: the greyed-out Add Shortcut button's tooltip shows the exact command for your install, and the same line is written once to client-main.log for copying. It looks like:

DOTNET_STARTUP_HOOKS='<data folder>/ModConfig/BetterMods/BetterModsHook.dll' '<game folder>/Vintagestory'

A launcher script that only sets the variable when the file is really there (Linux data folder is normally ~/.config/VintagestoryData):

#!/bin/sh
HOOK="$HOME/.config/VintagestoryData/ModConfig/BetterMods/BetterModsHook.dll"
if [ -f "$HOOK" ]; then export DOTNET_STARTUP_HOOKS="$HOOK"; fi
exec '<game folder>/Vintagestory' "$@"
Why the hook is not inside the mod
  • The runtime needs a real file on disk before the game starts; a zip's contents are not files until the game unpacks them at world load.
  • The game's unpack folder gets a new name with every release, so a shortcut pointing there would break on the next update - and a hook path to a missing file stops the game launching.
  • A loose .dll in a Mods folder is treated as a broken mod.
  • ModConfig\BetterMods\ is never scanned for mods, survives updates, and follows --dataPath.

Updates and safety

  • Downloads only when you click Update, Update all or Fix dependencies - and only on the main menu.
  • https only, mod DB only: files come from mods.vintagestory.at and its download server moddbcdn.vintagestory.at, checked again after redirects.
  • Verified before use: each download must be a valid zip whose modinfo.json names exactly the mod and version that was asked for. Retracted and blocklisted releases are never installed.
  • Never overwrites a file, and never deletes an old version.
  • Fails safe: if a game update breaks one of BetterMods' patches, that part goes back to the vanilla behaviour instead of crashing. If another mod strips all Harmony patches when you leave a world, BetterMods puts its own back.
  • Profiles are protected: an unreadable profiles file is never overwritten; a damaged one is kept as bettermods.json.corrupt and the last good .bak is used.

Multiplayer

  • Client-only. Not needed on servers, not visible to them, works on any server.
  • What a server requires is handled by the game's own mod download screen; profiles only decide what your client has enabled.
  • The in-game dialog works while connected; changes apply on your next world load or join.
  • World binding is singleplayer only. On a server BetterMods binds no profile, records no mod list and posts no chat notices; the world-start prompt only ever appears for your own singleplayer worlds.

Network use

BetterMods talks only to the mod DB set in the game (default https://mods.vintagestory.at) and its download server:

  • Update check - once per session when you first open the Mods screen or the in-game dialog, and when you ask: sends your game version and the ids and versions of your installed mods (core mods and BetterMods excluded).
  • Open mod page - one lookup of that mod's page address, on click.
  • Downloads - only the releases you chose to install.

No telemetry, no other sites.

Compatibility

  • BetterMods patches the vanilla Mods screen, its mod list rows, the singleplayer world list tooltip, the singleplayer world start and the Create New World playstyle list. Other mods that change the same screen may conflict.
  • Every patch checks its target first: if a game update moves something, that piece is skipped and stays vanilla rather than breaking the menu.
  • Switching BetterMods off in the mod manager disables it completely, including when launched through the shortcut.

Known issues and FAQ

Show known issues and FAQ
  • No tabs on the main menu? Load a world once, or use Add Shortcut. With the hook, check Logs/bettermods-hook.log.
  • How do I open the in-game dialog? It has no key by default: bind one to Mod Profiles under Settings > Controls.
  • "Restart needed - version changed"? You picked another version of a mod you already played with this session. Restart, or pick the version you were using.
  • "No newer releases for 1.23.0-pre.1"? Not "up to date" - nothing on the DB is tagged for your exact version yet.
  • Applied a profile in game and nothing changed? It takes effect at the next world load.
  • A mod I added by hand is on in every profile. Profiles record what is off, so new mods start on everywhere; a profile that had an older version on moves to the newest. Updates BetterMods installs itself only switch the profile you were viewing.
  • A mod copied in while the game runs is missing. Press Reload Mods, as in vanilla.
  • Odd characters show as ? - the card font is ASCII-only.
  • The game will not start after setting DOTNET_STARTUP_HOOKS myself. Remove the variable and use the shortcut instead.
Where BetterMods keeps its data

Under %APPDATA%\VintagestoryData\ on Windows (or your --dataPath):

  • ModConfig\bettermods.json (+ .bak) - profiles, singleplayer world bindings, recorded mod lists, trusted sites
  • ModConfig\BetterMods\BetterModsHook.dll - the startup hook
  • Mods\ - updates and dependencies it downloads
  • Logs\bettermods-hook.log - the hook's log
  • Each singleplayer save - a small record of its profile and mod list
  • Playstyles\*.vsplaystyle - saved playstyles (yours and other mods')

Uninstalling: remove the zip. The game keeps the last profile you applied. Optionally delete the desktop shortcut, ModConfig\BetterMods\ and ModConfig\bettermods.json with the game closed. A leftover hook and shortcut are harmless - the game just starts normally.

Bug reports

Please report bugs in the comments (or the Issues tab, where linked) with:

  1. Your game version and BetterMods version.
  2. Logs/client-main.log - BetterMods' lines start with [BetterMods].
  3. Logs/bettermods-hook.log if you use the startup hook.
  4. What you clicked, what you expected, and a screenshot if it is visual.
