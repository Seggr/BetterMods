Mod profiles for Vintage Story's mod manager + custom "Playstyles". Keep named sets of enabled and disabled mods, switch between them with one click, pick which installed version of a mod each profile uses, and update your mods from the mod DB - all inside the game's own Mods screen.

Lets be clear: this is a filthy Hack of a mod

This mod introduces features I believe should be stock in the game, and I hope the developers look at this and say "oh yes, he is correct; this is how it should be" and then implement everything it does. They don't even need to say thank you, I'll know ;3

Why is this a hack? Because it requires abusing .net to do what I want

Vintage Story runs no mod code before a world loads - the main menu only reads mod metadata. So on a normal launch the Mods screen stays vanilla until you have loaded a world once that session.

The fix is a small .NET startup hook, BetterModsHook.dll, which the .NET runtime itself runs before the game starts. It waits for the game to finish starting, then loads BetterMods' patches, so the profile tabs are there from the very first screen. It does nothing else, and it changes nothing once a world is loaded.

The catch: .NET only runs a startup hook when the DOTNET_STARTUP_HOOKS environment variable names it, and a mod has no way to set that for the game. So BetterMods makes a custom desktop shortcut, Vintage Story (BetterMods), from the Add Shortcut button on its own mod card. The shortcut sets that variable for that one launch only - and only if the hook file is actually there - then starts the game. Launch from the shortcut and the hook runs; launch the game normally and everything stays vanilla until a world loads. Nothing on your system is changed globally.

Main-menu Mods screen: profile tabs above the mod list, mod cards with update buttons, the update status with Update all, and Apply Profile

Installing

  1. Click the one-click link thing
  2. Confirm
  3. Open a world, then exit back to the main menu. BetterMods can't do anything until a world has loaded once - that's the hack.
  4. In Mods, click Add Shortcut on BetterMods' own card (Windows; on Linux/macOS see Linux and macOS).
  5. Close the app and open using the new desktop link or whatever abortion you produce to open the game.
    1. OR TECHNICALLY you don't have to restart right now - after step 3 the menu already works for the rest of this session... but you would still need to use the link next time, it's really not that hard.
  6. Manage your mods.

Features

  • Profiles as tabs - one per profile; + copies the one you are viewing, right-click to rename or delete. Apply Profile writes the game's own settings.
  • One card per mod - several installed versions share a card with a version drop-down; each profile can use a different version.
  • Update checking against mods.vintagestory.at, with Update all and a (Retracted) note.
  • Fix dependencies - switches on, or downloads, what a mod needs.
  • Singleplayer worlds remember their mods and offer the matching profile.
  • In-game dialog - the same tools without leaving the world.
  • Saved playstyles on Create New World.
  • Restart only for a version swap - enabling and disabling mods never needs one.

Load at startup (the startup hook)

Why this is needed: see Why is this a hack? above.

The easy way: Add Shortcut (Windows)

  1. Load any world once with BetterMods installed (the button is also in the in-game dialog).
  2. On BetterMods' own card, click Add Shortcut.
  3. From now on, start the game from the desktop shortcut Vintage Story (BetterMods).
BetterMods' own card with the Add Shortcut button, greyed out once the shortcut exists
  • For that launch only: the shortcut sets DOTNET_STARTUP_HOOKS just for the game it starts, and only if the hook file exists - delete the file and it still starts a normal game.
  • Nothing to copy by hand: BetterMods writes the hook to ModConfig\BetterMods\BetterModsHook.dll and keeps it matching the installed version, even after updates.
  • The button greys out once the shortcut exists - hover the card to see which shortcut it found. If creating it fails, the Mods screen says "Add Shortcut failed" and the card's tooltip gives the reason. Starting the game any other way gives the normal behaviour.
  • Off means off: switch BetterMods off in the mod manager and the hook does nothing either, from the next launch.

Never set DOTNET_STARTUP_HOOKS globally. If it points at a file that is missing or not a valid startup hook, the game does not start at all - no error dialog, no log.

  • Do not set it machine-wide or per-user (setx or the system settings) - every .NET program would try to load it.
  • Do not edit Vintagestory.runtimeconfig.json - a bad path there stops the game launching, and every game update overwrites the file.
Making the Windows shortcut by hand

Right-click the desktop, New > Shortcut, then in its Properties set:

Target %SystemRoot%\System32\cmd.exe /c if exist "%APPDATA%\VintagestoryData\ModConfig\BetterMods\BetterModsHook.dll" (set "DOTNET_STARTUP_HOOKS=%APPDATA%\VintagestoryData\ModConfig\BetterMods\BetterModsHook.dll") & start "" "GAMEFOLDER\Vintagestory.exe"
Start in GAMEFOLDER
Run Minimized
Icon GAMEFOLDER\Vintagestory.exe

Replace GAMEFOLDER with your install folder (installer default: %APPDATA%\Vintagestory). With a custom data folder, use <data folder>\ModConfig\BetterMods\BetterModsHook.dll for both hook paths and add --dataPath "<data folder>" at the end.

If the Target box cuts the line off (about 260 characters), save this as Vintage Story (BetterMods).cmd and launch from it instead:

@echo off
set "HOOK=%APPDATA%\VintagestoryData\ModConfig\BetterMods\BetterModsHook.dll"
if exist "%HOOK%" set "DOTNET_STARTUP_HOOKS=%HOOK%"
start "" "GAMEFOLDER\Vintagestory.exe"

The hook file only exists after BetterMods has run once, so load a world once first.

Linux and macOS

No shortcut is made. The greyed-out Add Shortcut button's tooltip shows the exact command for your install, and the same line is written once to client-main.log:

DOTNET_STARTUP_HOOKS='<data folder>/ModConfig/BetterMods/BetterModsHook.dll' '<game folder>/Vintagestory'

To keep the game launchable if the hook file is ever missing, use a script that sets the variable only when the file is there (Linux data folder is normally ~/.config/VintagestoryData):

#!/bin/sh
HOOK="$HOME/.config/VintagestoryData/ModConfig/BetterMods/BetterModsHook.dll"
if [ -f "$HOOK" ]; then export DOTNET_STARTUP_HOOKS="$HOOK"; fi
exec '<game folder>/Vintagestory' "$@"
Profiles

A profile is a named list of which mods are on and which are off. Profile 1 is created from whatever was enabled when BetterMods first ran, so nothing changes until you change it.

Right-clicking a tab opens the rename panel under it: name field, Delete, Enter saves, Esc cancels
  • Tabs: left-click to view and edit a profile. + creates "Profile N" as a copy of the one you are viewing. Right-click to rename (Enter saves, Esc cancels) or delete (second click confirms). The last profile cannot be deleted.
  • Viewed vs active: the selected tab is the one your clicks edit; the active profile is the one the game loads. The Mods screen always opens on the active one.
  • Toggling a mod edits the viewed profile only. On the main menu, if that is also the active profile, the change goes straight to the game like vanilla; otherwise it waits for Apply Profile.
  • Apply Profile makes the viewed profile active: it writes the game's own settings, so the game boots with that set every launch, with or without BetterMods. Deleting the active profile applies the first remaining one.
  • Mods the game changes itself (for example when joining a server) are folded into the active profile. Blocklisted mods stay blocked.
  • Profiles live in ModConfig\bettermods.json (plus a .bak). If it exists but cannot be read, BetterMods shows "Not saving - config unreadable" and never overwrites it.

The same tabs, cards, version picker and Apply Profile, inside a running world. Bind a key to Mod Profiles under Settings > Controls (none by default). In game, Apply Profile takes effect at the next world load - no restart, except for the version case below.

Mod cards, versions and the restart notice
Card tooltip: name, mod id, version and side on one line; authors; description; then dependencies, an update for an older game version and the retraction reason
  • Fixed-height cards: icon, title and version on top, buttons along the bottom (Add Shortcut, Fix dependencies, Open mod page, Update to x.y.z). Hover for authors, description, dependencies and update details.
  • Yellow triangle by the version: an update is available. (Retracted): the installed release was retracted on the mod DB; the tooltip gives the reason.

  • Several versions of one mod share one card. Click the arrow on the version label and pick one: it is switched on in the viewed profile and the others are switched off.
  • Restart notice: the game cannot swap the code of a mod it already loaded this session. Pointing a profile at a different version of such a mod shows "Restart needed - version changed". Never after a fresh launch, for mods that are off, for content-only mods, or for plain enable/disable.
Update checking and installing
Yellow update markers with Update to buttons: updates for an older game version show (1.22), an exact-version update does not, and a retracted release shows (Retracted)
  • When: once per session in the background, the first time you open the Mods screen or the in-game dialog; again on Reload Mods or the status button. Never on a timer.
  • Exact game version only: an update is offered only for a newer release tagged for the exact version you run (e.g. 1.23.0-pre.1). Never stable onto pre-release.
  • Older game version: with nothing for your version, BetterMods also looks at the newest stable version before it (e.g. 1.22.7). Those show a yellow Update to x.y.z (1.22), ask you first, and are not included in Update all.
  • Honest wording: few mods are tagged for a preview build yet, so the status says "No newer releases for 1.23.0-pre.1", never "up to date".
  • Not checked: core mods, BetterMods itself, mods whose modinfo failed to load, and anything inside the game folder.
Tooltip of a mod with an update tagged for the exact game version: the green Update available line (Also Bannta you should go lookup what Semver is and what the numbers mean)

Installing happens only when you click Update to ... or Update all, and only on the main menu:

  • Old versions are never deleted - the new file goes next to the old one and both stay in the version drop-down.
  • Only the viewed profile switches to the new version; every other profile keeps its own.
  • Every download is checked - see Safety below.
Open mod page and trusted links

BECUASE I DON'T WANT TO HIT CONFIRM EVERY TIME

  • Open mod page is on the card of every mod the update check found on the DB. It looks the page up once per mod per session and opens it in your browser.
  • The first time, you choose Cancel, Always trust mods.vintagestory.at, or Open. Trust applies only to the mod page links BetterMods builds itself; every other link keeps the game's normal confirmation.
  • To undo "Always trust": with the game closed, remove the site from "TrustedLinkHosts" in ModConfig\bettermods.json. There is no in-game switch.
Fix dependencies

A mod that is on in the viewed profile, with a dependency that is missing, off or too old, gets a yellow Fix dependencies button; the tooltip lists each problem. Clicking it, for the viewed profile only:

  1. Uses what you have - switches on the newest installed version that satisfies the requirement.
  2. Downloads what is missing (main menu only) - the newest release for your game version, or, after asking, one for the older game version.
  3. Follows the chain - a new dependency's own dependencies are fixed too.

Anything it could not do is listed in the status line, the tooltip and the log - nothing is half-done silently. Requirements on the game itself (game, survival, creative, other core mods) are shown and left to you.

Worlds remember their profile and mods (singleplayer only)
Singleplayer world list: hovering a world shows, at the bottom of its tooltip, the BetterMods profile it is bound to and the mods it last loaded with
  • Singleplayer only. Starting one of your singleplayer worlds binds it to the active profile and records which mods it loaded with. On a multiplayer server: no binding, no recorded mod list, no chat notice.
  • One prompt, only when it matters: mods the world used are not enabled, another profile matches the world exactly, or the world is bound to a different profile. Version differences and extra mods alone never ask.
  • Switch to ... applies the suggested profile and starts the world. Play with ... starts it as it is and rebinds it. Cancel goes back.
  • World list tooltip: a world's profile and the mods it last loaded with.
  • Copied worlds: a small record inside the save travels with it. Never written into a read-only save, one being upgraded, or one being repaired.
  • Without the startup hook the first world of a session starts before BetterMods runs, so instead of a prompt you get a [BetterMods] chat line if something did not match.

Saved playstyles (Accepted feature creep)

Accepted feature creep. This has nothing to do with mod profiles. It lives in BetterMods because I'm lazy, and a separate mod just for two buttons on one screen was not worth it.

Create New World with Save and Delete playstyle, and a saved custom playstyle
  • Save playstyle (on the Select A Playstyle row of Create New World) saves the selected playstyle, everything you changed under Customize and the world height under a name. The seed and world name are never saved.
  • Saved playstyles appear in the list tagged Custom with a line like "Based on Standard, world height 256.". Picking one applies all its settings and its height.
  • Delete playstyle asks first, and is disabled for the game's own playstyles, ones mods define in worldconfig.json, and files a mod marked read-only.
  • Worlds stay vanilla: a world is created as the base playstyle with the saved settings applied, and loads the same without BetterMods.
  • A missing base playstyle greys the entry out as Unavailable - the only thing that blocks an entry. Settings it cannot use (missing mods, unknown keys, invalid values) are skipped and the entry still loads; hover it to see what was skipped.
For mod authors: the .vsplaystyle format

Any mod (or player) can add playstyles by writing <name>.vsplaystyle files (UTF-8 JSON, name from A-Z a-z 0-9 _ -, 1-128 characters) directly into <data path>\Playstyles\ - exactly what api.GetOrCreateDataPath("Playstyles") returns.

{
  "format": "vsplaystyle",
  "name": "Hardcore Survival",
  "description": "Survive and Build with one life and harsh winters.",
  "basePlaystyle": "surviveandbuild",
  "worldHeight": 320,
  "worldConfig": { "playerlives": "1", "harshWinters": "true", "graceTimer": "0" },
  "readOnly": true,
  "author": "YourMod"
}
  • format (optional): "vsplaystyle" - a type marker, never checked; the .vsplaystyle extension is what counts. There is no version number: unknown fields are ignored, including the formatVersion, gameVersion and createdBy older files carry, so those keep loading.
  • basePlaystyle (required): a real playstyle code; the world is created as it. worldConfig: sparse overrides keyed by world-config attribute code, as in a worldconfig.json playstyle.
  • worldHeight (default 256): rounded to 128-512 in steps of 64 (to 2048 for creativebuilding).
  • readOnly: true for files your mod supplies - never deleted or overwritten, tagged "By <author>" (or "From a mod").
  • Data only: plain JSON, nothing executed; at most 200 files of 64 KB. Only a file that is not JSON, has no basePlaystyle or has a bad name is skipped (and logged); a basePlaystyle that is not installed shows the entry as Unavailable. Each value is checked against its attribute (ranges clamped, dropdowns must match, no < or > in text); a rejected value keeps the base value and unknown keys are skipped - the entry still loads, and its tooltip and the log say what was skipped.

Safety

  • Downloads only when you click Update, Update all or Fix dependencies, and only on the main menu.
  • https only, mod DB only: mods.vintagestory.at and its download server moddbcdn.vintagestory.at, checked again after redirects.
  • Verified before use: each download must be a valid zip whose modinfo.json names exactly the mod and version asked for. Retracted and blocklisted releases are never installed.
  • Never overwrites a file, and never deletes an old version.
  • Fails safe: a patch broken by a game update falls back to vanilla instead of crashing. If another mod strips all Harmony patches, BetterMods puts its own back.
  • Profiles are protected: an unreadable file is never overwritten; a damaged one is kept as bettermods.json.corrupt and the last good .bak is used.

Multiplayer

  • Client-only. Servers do not need it, do not see it, and it works on any server.
  • What a server makes you load is up to the server and the game's own mod download screen; profiles decide only what your client has enabled.
  • World binding is singleplayer only - on a server BetterMods binds no profile, records no mod list and posts no chat notices.

Network use

BetterMods contacts only the mod DB set in the game (default https://mods.vintagestory.at) and its download server:

When What is sent / fetched
First open of the Mods screen or dialog per session; Reload Mods; the status button Your game version and the ids and versions of your installed mods (core mods and BetterMods excluded), plus the DB's list of game versions
Open mod page One lookup of that mod's page address (cached for the session)
Update, Update all, Fix dependencies Downloads of the releases you chose

Nothing else: no telemetry, no other sites. Opening a mod page hands the address to your browser.

Known limitations and FAQ
  • No tabs on the main menu? Load a world once, or use Add Shortcut. With the hook, check Logs\bettermods-hook.log.
  • Zip install + hook: the first launch after installing or updating BetterMods is vanilla until a world loads (the game only unpacks zips then). Folder installs have no gap.
  • "Restart needed - version changed"? You picked another version of a mod you already played with this session. Restart, or pick the version you were using.
  • "No newer releases for 1.23.0-pre.1"? Not "up to date" - nothing on the DB is tagged for your exact version yet.
  • Applied a profile in game and nothing changed? It takes effect at the next world load.
  • A mod I added by hand is on in every profile. Profiles record what is off, so new mods start on everywhere, and a profile that had an older version of it on moves to the newest. Updates and dependencies BetterMods installs itself only go to the viewed profile.
  • A mod copied in while the game runs is missing. Press Reload Mods, as in vanilla.
  • Odd characters show as ? - the card font is ASCII-only.
  • Windows-only shortcut. On Linux and macOS you add the launch command yourself. The shortcut also cannot be made if a path contains % or ".
  • Saved playstyles based on Creative Building are not treated as creative by the game's new-world checks, and Customize caps the height at 512. The world is still created as Creative Building.
  • The game will not start after setting DOTNET_STARTUP_HOOKS myself. Remove the variable and use the shortcut instead.
  • BetterMods patches the vanilla Mods screen; another mod changing the same screen may conflict.
Where BetterMods keeps its data, and uninstalling

Under %APPDATA%\VintagestoryData\ on Windows (or your --dataPath):

  • ModConfig\bettermods.json (+ .bak) - profiles, world bindings, recorded mod lists, trusted sites
  • ModConfig\BetterMods\BetterModsHook.dll - the startup hook
  • Mods\ - updates and dependencies it downloads
  • Logs\bettermods-hook.log - the hook's log
  • Each singleplayer save - a small record of its profile and mod list
  • Playstyles\*.vsplaystyle - saved playstyles

Uninstalling: remove the zip; the game keeps the last profile you applied. Optionally, with the game closed, delete the desktop shortcut, ModConfig\BetterMods\ and ModConfig\bettermods.json. A leftover hook and shortcut are harmless - the game just starts normally.
